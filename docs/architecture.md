# 记个账实现设计

- Kotlin / Compose 的单 Activity 应用。页面通过 ViewModel 调用 LedgerRepository，所有金融数据和个人资料保存在 Room + SQLCipher。API Key 与数据库主密钥由 Android Keystore 中的 AES-GCM 密钥保护。App 禁用系统云备份和设备传输。
- 金额以整数分存储。流水保留内部时间戳和录入的日历日期，单独记录是否填写了时分。列表默认隐藏关联账户和时分，详情可查看和编辑账户与日期，不再展示或编辑时分；原时间戳仍用于排序和余额校准。统计按日历日期归属，校准按时间戳精确比较。每个账户仅保留最近一次基准余额和时间，余额由基准与之后的关联流水推算。改流水或换账户时没有额外余额写入。个人设置和资产页共用净资产合计，账户不再提供归档和恢复操作；旧版归档记录继续保留在加密库及备份中，资产页隐藏且不计入净资产，已有流水关联保留。个人设置默认隐藏净资产精确值，眼睛按钮独立控制本次会话的显示状态。
- 信用卡、美团月付、花呗等统一为 CREDIT「信用账户」，使用带符号余额，欠款为负值、溢缴为正值。添加和校准界面用欠款口径输入，Repository 负责转换符号。信用消费按支出扣减余额，还款转入增加余额，净资产直接汇总带符号余额。
- Room v7 → v8 将旧 CREDIT_CARD、MEITUAN_CREDIT、HUABEI 分类统一为 CREDIT，保持账户标识、名称、余额、校准点和关联不变；旧备份在解析时做相同转换。
- Room v6 → v7 增加独立的 transfers 表，以一条记录表达转出、转入账户和金额，避免单边入账。两端分别遵守各自的校准时间，编辑和删除后统一重算余额。首页按日期和时间合并展示收支与转账，统计、趋势图及 AI 报告读取收支记录。v8 备份包含转账并兼容恢复 v1 至 v7。AI 导入将明确的本人信用账户还款本金视为账户互转，单列手续费和利息按支出处理。
- 每笔流水关联同方向的一个标签。标签归档不会删历史数据；修改标签名后历史账单和统计使用新名称。方向相同的标签不能同名。支出可额外关联一个可复用的自建场景，类型与场景分别存储。Room v1 → v2 使用加密库原地迁移，旧流水的场景为空。
- AI 采用固定 HTTPS 官方地址、禁止重定向。周报、月报、年报基于本地汇总，提供分段已覆盖天数、金额集中度、高频类型和同类型场景对照。两个完整周期都有流水时提供上期总收支对比。提示词优先寻找容易忽略的支出惯性和有证据的风险，要求同类、同口径的连续记录才能判断惯性变化。模型输出一个主要发现及可选的补充和观察建议。正文与发送摘要的版本签名一起保留，提示词升级后可重新生成旧报告。
- 统计环形图与明细共用选定期间的金额汇总。支出按类型与场景分别展示，收入按类型展示。场景覆盖全部支出，未标场景单列。超过五个的具名分类在图中归到「其余」，列表保留各项明细。
- 周筛选固定周一至周日。周报使用整周口径。点周趋势里的某一天可查看当天收支，周看板、占比和分类明细继续按自然周计算。已有日报继续保留在本机和备份中。
- AI 导入账单使用与报告独立的逐文件确认。发送所选文件的图像或提取文本，以及每组最多 100 个已有场景／类型名称。模型按交易线索推荐分类。预览保留原建议供对照，用户可在保存前更换、填写类型或清空场景。与本机已有流水日期、金额、方向相同的候选默认不勾选。保存用单个 Room 事务，识别批次的稳定记录标识用于拦截重复提交。导入账户留空。
- Room v5 → v6 增加可选时分标记和定时账单。精度不明的旧流水保留原时间戳（时分入口已在 0.9.3 移除）。无时间的导入和定时补记用原日期的起点作为内部时间戳，快捷记账和当天生成的定时流水使用生成时刻用于余额校准。v7 备份保留时分标记、定时账单和最后已处理日期。
- 定时账单以首次日期为重复锚点，月末和闰日按目标月有效日期截短。启用规则后登记持久化的 Android JobScheduler 任务，系统安排后台检查，前台打开和换日时也检查。到期流水用规则与计划日期生成稳定标识，并与最后已处理日期在同一事务写入。系统延迟后按原日期补记。关联标签或账户不可用时暂停生成，恢复关联后可以补记。删除规则保留已生成的流水。
- 分类习惯从最近的有效流水在本机计算。只有跨天重复、领先于其他组合的匹配才预选，手动选择优先。导入识别后使用本机习惯重新分类，修改一笔后可按商家、时间和金额筛出相似候选并检查后同步。位置功能默认关闭，开启后只在新建流水页面使用粗略位置，保存带设备随机盐的网格标记。位置范围不上传、不参与导出，关闭即清除。
- 标签管理、录入页多行标签和资产账户使用 [Compose DND](https://github.com/MohamedRejeb/compose-dnd/tree/v1.0.0-alpha01) 处理长按拖动、边缘滚动与松手动画。Room v2 → v3 为类型标签和场景增加可空顺序列，v3 → v4 为账户增加顺序和默认关联标记。拖动后在事务中保存顺序，资产和关联账户选择器共享账户顺序。
- 没有明确习惯匹配时，新支出默认选中排在第一位的场景，类型留空。未手动指定账户的新流水跟随唯一的默认账户。归档默认账户时在同一事务中取消默认标记，已保存流水保留原关联。
- Room v4 → v5 增加类型和场景的 Lucide 图标、颜色，以及本机位置范围。图标配置经预览提交，AI 请求只包含待配置的标签名称和方向。模型之外可用本机语义规则推荐，并可手动挑选。新建标签或场景时先对临时名称生成单标签建议，保存时与名称一并写入，标签管理列表直接复用该图标。v6 备份增加图标与颜色，兼容导入 v1 至 v5。导出取得一致快照并通过 FileProvider 分享。导入在内存中校验后用 Room 事务替换数据。
- 首版用单元测试验证金额、跨年统计、校准边界；模拟器测试覆盖记账交互、账户变更、跨账本备份和模型请求范围。
- 周月年、收支、外观等筛选使用同一个分段控件。浅色主题统一使用白色容器，深色主题使用深色容器。
- 底栏使用 [AndroidLiquidGlass 的 Backdrop 1.0.6](https://github.com/Kyant0/AndroidLiquidGlass/tree/1.0.6)，实时采样穿过底栏的列表和背景。Android 13 起支持动态折射与色散，Android 12 使用背景模糊，Android 8 至 11 使用静态半透明材料。底栏最宽 224dp，默认高 58dp，大字号时随标签行高增加。「账本」和「统计」分列两侧，点按即时切页。点按标签与记账按钮使用系统触感反馈。选中胶囊使用 32% 不透明度的灰色平面背景，浅色主题搭配亮蓝图文，深色主题搭配高亮浅蓝图文，外缘高光由底栏容器绘制。速度形变和边缘阻尼应用在选中胶囊上，胶囊可从居中的小尺寸扁圆记账按钮下方滑过。记账按钮使用青蓝到宝蓝的横向渐变，只显示加号，读屏名称为「记一笔」，四周保留独立留白。拖动松手后吸附到最近标签，取消时回到原标签。点击记账按钮打开固定的自定义数字键盘，返回到发起页。资产从个人设置打开，返回父页面。个人设置按头像、资产、标签、AI、外观、备份、关于排列，备份与关于直接由菜单组表达层级。
- 收支和转账编辑共用 EntryEditorLayout 与 EntryComposer：竖屏分类区域独立滚动，账户在金额卡片上方单独显示，卡片内金额下方由日期与占剩余宽度的备注共用一行，数字键盘固定在底部；横屏采用左右分列，账户移至左侧分类区域，右侧保留金额、日期、备注与键盘。金额输入不申请系统 IME，备注弹窗继续使用系统文字输入。日期入口直接打开日历，不提供时分选择；变更日期仍通过 changedOccurrenceTime 保持校准语义，未变更日期的旧记录保留时间戳与精度元数据。导入账单的来源时间仅保留内部用途，核对页面不展示时分字段。加减表达式按整数分计算，限制每个操作数最多两位小数，未完成表达式、非正数或超限金额不能保存。草稿与表达式使用 rememberSaveable，切换方向与配置变化后保留；保存时只向 Repository 传递最终整数分。进入编辑器清除上一页的提示，编辑器内的新提示在顶部显示，避免遮挡底部数字键和保存键。
- 新建流水使用独立于横向详情页的垂直转场：记账页从底部滑入，右上角关闭按钮或系统返回让整页在 340 毫秒内向下滑出，淡出延后 80 毫秒，并回到发起时的页面和标签。编辑既有流水继续使用返回按钮与普通页面转场。

## 图标

Android 桌面图标是自适应图标。蓝色渐变作为背景，瓷白账本和「¥」作为透明 PNG 前景，前景可见轮廓统一到 432px 画布中央的 180px 正方形，四边透明留白各 126px，系统按设备的桌面图标形状裁切。

应用界面使用 [Lucide 官方图标](https://github.com/lucide-icons/lucide/tree/55782beff3a0133df79c417eb68f96e8f19e2404/icons) 的 Android 矢量资源。各资源记录了上游 SVG 路径和版本，许可证随 APK 一起打包。
